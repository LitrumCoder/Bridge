# Ручные проверки

Что автотесты проверить не могут: настоящие ОС, разрешения, железо, DAW, телефон. Каждый пункт —
шаги и ожидаемый результат. Перед выпуском этапа проходится весь список на двух реальных компьютерах
(любая пара Windows / macOS / Linux X11), MIDI-клавиатуре, DAW и телефоне.

Обозначения: **A** — компьютер, к которому подключены мышь и клавиатура; **B** — второй компьютер.

## Сопряжение и сеть (веха 3)

| # | Шаги | Ожидается |
|---|---|---|
| P1 | Запустить `bridged` на A и B в одной сети. На B: `bridge pair --show`. На A: `bridge nearby` | B виден в списке с именем и адресом |
| P2 | На A: `bridge pair <начало отпечатка B> <код>` | «paired with …»; `bridge devices` на обоих — устройство в статусе connected |
| P3 | Повторить P2 с неверным кодом | «the code does not match»; окно на B закрыто; верный код после этого не работает до нового `--show` |
| P4 | Три неверных кода подряд | Четвёртый `--show` отказывает с блокировкой на 5 минут |
| P5 | QR: `bridge pair --show` на B, отсканировать QR телефоном (после вехи 10) или вставить ссылку: `bridge pair --uri "<ссылка>"` | Сопряжение без ввода кода |
| P6 | Перезапустить `bridged` на обоих | Соединяются сами за несколько секунд |
| P7 | Сеть без mDNS (гостевой Wi-Fi с изоляцией): `bridge pair <IP:47800> <код>` | Сопряжение по адресу; после перезапуска соединяются по запомненному адресу |
| P8 | На B: `bridge unpair <A>` | На A устройство B исчезает из `bridge devices`, повторных попыток соединения нет |
| P9 | Windows: первый запуск `bridged` | Появляется запрос брандмауэра; после разрешения для частных сетей всё работает |

## Общий курсор и клавиатура (вехи 4a–4c)

Логика (геометрия, маршрутизация, залипания) покрыта автотестами вехи 4a на mock-платформе.
Пункты ниже относятся к настоящим ОС и выполняются после вех 4b (Windows, X11) и 4c (macOS, Wayland).

| # | Шаги | Ожидается |
|---|---|---|
| I1 | Расположить B справа от A. Увести курсор за правый край A | Курсор появляется у левого края B на той же физической высоте; на A курсор скрыт, ввод не доходит до A |
| I2 | Мониторы с разной плотностью (4K 27" и 1080p 14") | Нет скачка по высоте; физическая скорость курсора одинакова |
| I3 | Набрать текст на B, включая Shift, Ctrl+C/Ctrl+V | Символы и сочетания работают; при управлении Mac — Ctrl превращается в Cmd |
| I4 | Удерживая Shift, перевести курсор обратно на A, отпустить Shift | На B Shift не залип, на A не зажат |
| I5 | Удерживая клавишу на B, выдернуть сетевой кабель / выключить Wi-Fi на A | На B через ≤ 3 с клавиша отпущена; на A курсор вернулся |
| I6 | Ctrl+Alt+L на A, когда курсор на B | Курсор не уходит с экрана B (игровой режим); повтор снимает блокировку |
| I7 | Ctrl+Alt+F1 / F2 | Курсор переходит на устройство 1 / 2 в порядке раскладки |
| I8 | Ctrl+Alt+Shift+Esc, когда курсор на B | Управление сразу возвращается на A |
| I9 | Потрясти мышью на B | Показывается локатор курсора (оверлей — веха 4b) |
| I10 | Переключить раскладку (ru/en) на A и перейти на B | На B включается та же раскладка |
| I11 | Окно с правами администратора на Windows B | Ввод в него не доходит (ограничение UIPI, см. LIMITATIONS) — B остаётся управляемым в других окнах |
| I12 | macOS: первый запуск без Accessibility | Понятный онбординг с кнопкой открытия настроек; после выдачи — работает |
| I13 | GNOME 46+ / KDE 6.1+ на Wayland | Диалог портала, после разрешения — общий курсор; Sway — сообщение и режим хоткея |
