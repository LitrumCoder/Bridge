# Ручные проверки

Что автотесты проверить не могут: настоящие ОС, разрешения, железо, DAW, телефон. Каждый пункт —
шаги и ожидаемый результат. Перед выпуском этапа проходится весь список на двух реальных компьютерах
(любая пара Windows / macOS / Linux X11), MIDI-клавиатуре, DAW и телефоне.

Обозначения: **A** — компьютер, к которому подключены мышь и клавиатура; **B** — второй компьютер.

## Сопряжение и сеть (веха 3)

| # | Шаги | Ожидается |
|---|---|---|
| P1 | Запустить `bridged` на A и B в одной сети. На B: `bridge pair --show`. На A: `bridge nearby` | B виден в списке с именем и адресом |
| P2 | На A: `bridge pair <начало отпечатка B> <код>` | «paired with …»; `bridge devices` на обоих — устройство в статусе connected |
| P3 | Повторить P2 с неверным кодом | «the code does not match»; окно на B закрыто; верный код после этого не работает до нового `--show` |
| P4 | Три неверных кода подряд | Четвёртый `--show` отказывает с блокировкой на 5 минут |
| P5 | QR: `bridge pair --show` на B, отсканировать QR телефоном (после вехи 10) или вставить ссылку: `bridge pair --uri "<ссылка>"` | Сопряжение без ввода кода |
| P6 | Перезапустить `bridged` на обоих | Соединяются сами за несколько секунд |
| P7 | Сеть без mDNS (гостевой Wi-Fi с изоляцией): `bridge pair <IP:47800> <код>` | Сопряжение по адресу; после перезапуска соединяются по запомненному адресу |
| P8 | На B: `bridge unpair <A>` | На A устройство B исчезает из `bridge devices`, повторных попыток соединения нет |
| P9 | Windows: первый запуск `bridged` | Появляется запрос брандмауэра; после разрешения для частных сетей всё работает |

## Общий курсор и клавиатура (вехи 4a–4c)

Логика (геометрия, маршрутизация, залипания) покрыта автотестами вехи 4a на mock-платформе.
Пункты ниже относятся к настоящим ОС и выполняются после вех 4b (Windows, X11) и 4c (macOS, Wayland).

| # | Шаги | Ожидается |
|---|---|---|
| I1 | Расположить B справа от A. Увести курсор за правый край A | Курсор появляется у левого края B на той же физической высоте; на A курсор скрыт, ввод не доходит до A |
| I2 | Мониторы с разной плотностью (4K 27" и 1080p 14") | Нет скачка по высоте; физическая скорость курсора одинакова |
| I3 | Набрать текст на B, включая Shift, Ctrl+C/Ctrl+V | Символы и сочетания работают; при управлении Mac — Ctrl превращается в Cmd |
| I4 | Удерживая Shift, перевести курсор обратно на A, отпустить Shift | На B Shift не залип, на A не зажат |
| I5 | Удерживая клавишу на B, выдернуть сетевой кабель / выключить Wi-Fi на A | На B через ≤ 3 с клавиша отпущена; на A курсор вернулся |
| I6 | Ctrl+Alt+L на A, когда курсор на B | Курсор не уходит с экрана B (игровой режим); повтор снимает блокировку |
| I7 | Ctrl+Alt+F1 / F2 | Курсор переходит на устройство 1 / 2 в порядке раскладки |
| I8 | Ctrl+Alt+Shift+Esc, когда курсор на B | Управление сразу возвращается на A |
| I9 | Потрясти мышью на B | Показывается локатор курсора (оверлей — веха 4b) |
| I10 | Переключить раскладку (ru/en) на A и перейти на B | На B включается та же раскладка |
| I11 | Окно с правами администратора на Windows B | Ввод в него не доходит (ограничение UIPI, см. LIMITATIONS) — B остаётся управляемым в других окнах |
| I12 | macOS: первый запуск без Accessibility | Понятный онбординг с кнопкой открытия настроек; после выдачи — работает |
| I13 | GNOME 46+ / KDE 6.1+ на Wayland | Диалог портала, после разрешения — общий курсор; Sway — сообщение в журнале |
| I14 | macOS: двойной клик, перетаскивание окна, прокрутка трекпадом и колесом при управлении Mac с Windows | Двойной клик открывает файл, окно тянется, прокрутка в правильную сторону по обеим осям |
| I15 | macOS: при управлении с Mac зажать и отпустить Shift, Cmd, Option по отдельности и вместе; Caps Lock | На приёмнике модификаторы не залипают, Caps Lock переключается |
| I16 | macOS: отозвать Accessibility в настройках, пока `bridged` работает | Ввод Mac не зависает, общий курсор отключается, в журнале — понятная причина |
| I17 | Wayland: перезапустить `bridged` после первого разрешения RemoteDesktop | На GNOME/KDE повторного диалога нет (restore token) |
| I18 | Wayland: уйти курсором за край без соседа | Курсор остаётся у края, захват сразу отпущен |
| I19 | Принудительный X11 под Wayland: `BRIDGE_INPUT_BACKEND=x11 bridged` | Работает X11-бэкенд (видит только окна XWayland) |

## Буфер обмена (веха 5)

| # | Шаги | Ожидается |
|---|---|---|
| C1 | Скопировать текст на A (Блокнот / gedit), вставить на B | Тот же текст, переводы строк правильные (CRLF на Windows) |
| C2 | Скопировать форматированный текст из браузера на A, вставить в Word / LibreOffice на B | Сохраняется форматирование (HTML/RTF) |
| C3 | Скопировать скриншот (Win+Shift+S / `xclip -t image/png`) на A, вставить в Paint / GIMP на B | Картинка вставляется; пока не вставили — по сети ничего не передаётся (трафик в `bridge status`) |
| C4 | Скопировать пароль из KeePassXC / 1Password на A | На B буфер не меняется |
| C5 | Скопировать на B то, что пришло с A | На A не возникает повторного «изменения» (нет эха) |
| C6 | Скопировать большой файл-картинку 20 МБ, вставить на B через Wi-Fi | Вставка занимает несколько секунд, приложение не зависает дольше 15 с |
| C7 | `bridged --no-clipboard` на A | Буфер между A и B не синхронизируется, остальное работает |

## Файлы (веха 6a)

| # | Шаги | Ожидается |
|---|---|---|
| F1 | `bridge send <B> ~/Фото` (папка с подпапками, ~1 ГБ) | На B появляется `Загрузки/Bridge/Фото` с тем же деревом, размерами и датами изменения |
| F2 | Повторить F1 | Вторая копия — `Фото (1)`, первая не тронута |
| F3 | Во время F1 выключить Wi-Fi на A на 20 с и включить | Передача продолжается с места обрыва (`bridge transfers` на B: процент не сбрасывается), файл совпадает побайтно |
| F4 | `bridge cancel <id>` во время передачи | Обе стороны: `cancelled`; на B нет `.bridgepart` |
| F5 | Передавать 10 ГБ по Wi-Fi и одновременно водить курсором и играть на MIDI-клавиатуре через Bridge | Курсор и ноты без заметной задержки; скорость файла близка к полосе Wi-Fi |
| F6 | Файл > 10 ГБ | Память `bridged` не растёт выше ~100 МБ |
| F7 | `bridge permissions <A> --files off` на B, затем `bridge send` с A | Ошибка «does not accept files from us»; на B ничего не появляется |
| F8 | Имя файла `con.txt` или `a:b` на Linux, отправить на Windows | Отправитель отказывает с понятной ошибкой: имя недопустимо на других системах |

## Перетаскивание (веха 6b)

| # | Шаги | Ожидается |
|---|---|---|
| D1 | Windows A → Windows B: в Проводнике A схватить 2 файла и папку, утащить за край к B, отпустить на рабочем столе B | Файлы появляются на рабочем столе B; на A ничего не скопировано и не перемещено |
| D2 | То же, отпустить в окно DAW на B (Ableton / Reaper / FL Studio) | Сэмпл появляется в проекте; путь — из `staging` |
| D3 | Перетащить на B и нажать Esc до отпускания | На B ничего не появляется, на A перетаскивание закончилось без последствий; `bridge transfers`: `cancelled` |
| D4 | X11 A (Nautilus/Dolphin) → X11 B (Nautilus/Dolphin/Bitwig) | Как D1/D2 |
| D5 | Клик и перетаскивание окна у самого края экрана A без файлов | Клики и Aero Snap работают как без Bridge; курсор не уходит на B с зажатой кнопкой |
| D6 | Перетащить файл 5 ГБ | Приложение-цель ждёт окончания передачи; после — файл целиком |
| D7 | Wayland B: перетащить на него файлы с A | Файлы сохраняются в `Загрузки/Bridge` |
