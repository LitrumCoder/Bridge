# ADR-0014. Стратегия тестирования

Статус: Предложено

## Решение

### Уровни
1. **Юнит и property** (proptest) в `protocol`, `core`, `features/*`. Обязательные свойства: кодек round-trip
   и golden-байты; геометрия «край → обратно» с DPI; отсутствие нажатых клавиш после любой последовательности
   событий и разрывов; монотонность и полнота jitter-буфера; валидатор путей не пропускает выход за корень.
2. **Фаззинг** (cargo-fuzz, отдельный workspace `fuzz/`): `envelope`, сообщения каждой фичи, сопряжение,
   валидатор путей. В CI — 60 с на цель на каждый PR, по расписанию — 30 мин; корпус хранится в репозитории.
3. **Интеграционные** (`crates/testkit/tests`): 2–3 узла `bridge_node` в одном процессе, настоящий quinn,
   mock-платформа. Сценарии из ТЗ: сопряжение, переход туда-обратно, буфер, drag, MIDI, Pause/Leave/возврат,
   отказ неспаренному, несовместимая версия.
4. **Сетевые сбои.** `testkit::netsim` — собственная реализация `quinn::AsyncUdpSocket`: узлы общаются через
   виртуальную сеть в памяти с задержкой, джиттером, потерями, переупорядочиванием, разрывами и **узким
   горлом с очередью** (иначе bufferbloat не воспроизвести). `turmoil` не подходит — штатного способа подставить
   его сокеты в quinn нет. Точный API подключения своего сокета сверяется с docs.rs quinn 0.11 на вехе 2.
   Проверки: нет залипших клавиш; файлы докачиваются; MIDI без потерь и в порядке; p99 задержки ввода при
   параллельной передаче 2 ГБ (данные генерируются на лету) растёт не больше чем на 5 мс относительно
   тишины.
5. **Платформенные** (`--features platform-tests`):
   - Linux X11 под Xvfb: реальный XI2-захват и XTest-инъекция, тестовое окно проверяет полученные события;
     буфер обмена X11; ALSA seq виртуальные порты (модуль `snd-seq-dummy` на раннере, если доступен, иначе пропуск
     с явной пометкой в отчёте).
   - Windows: `SendInput` + LL-хуки на раннере (интерактивная сессия есть), буфер, именованный канал IPC.
   - macOS: CoreMIDI виртуальные порты, буфер; ввод — только сборка (TCC на раннере не выдаётся).
   - Остальное — `docs/MANUAL_TESTS.md`.
6. **Бенчмарки** (criterion 0.8): задержка «mock-захват → mock-инъекция» через QUIC на loopback, MIDI задержка
   и джиттер, скорость файлов, кодек. Цели — `benches/targets.toml`; скрипт сравнивает `estimates.json`
   с целями и роняет CI при превышении. Общие раннеры шумные, поэтому пороги в CI = цель × 2, а точные цели
   проверяются на эталонной машине (`cargo xtask bench --strict`). Начальные цели:
   - ввод захват→инъекция, loopback: p50 < 0.5 мс, p99 < 2 мс;
   - MIDI добавленная задержка без буфера, loopback: p99 < 1 мс; джиттер (stddev) < 0.3 мс;
   - файлы, loopback: ≥ 400 МБ/с;
   - кодек: encode+decode движения < 200 нс.
7. **Покрытие** — `cargo-llvm-cov`, порог 85% строк для `protocol` и `core`, CI падает ниже.
8. **Android** — JUnit, Compose UI на эмуляторе, инструментальный тест моста.
9. **Desktop-UI** — Vitest + Testing Library, Playwright (mock IPC), WebDriver + tauri-driver (Linux, Windows).

### CI (GitHub Actions)
Матрица `windows-latest`, `macos-latest`, `ubuntu-latest`: `fmt --check`, `clippy -D warnings`, тесты,
платформенные тесты; на Linux — `cargo deny`, покрытие, fuzz-smoke, бенчмарки, Xvfb; отдельная задача —
сборка Android (`cargo-ndk` + Gradle + эмулятор). Actions закреплены по SHA.
