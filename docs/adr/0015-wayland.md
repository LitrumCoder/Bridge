# ADR-0015. Linux Wayland

Статус: Предложено

## Контекст

Wayland намеренно не даёт глобального перехвата и инъекции. Официальный путь — порталы xdg-desktop-portal:
InputCapture (захват после барьера на краю) и RemoteDesktop с `ConnectToEIS` (инъекция), данные идут через libei.

Поддержка на октябрь 2026:
- GNOME 46+ — InputCapture и RemoteDesktop (версия 2 портала с буфером — GNOME 50+);
- KDE Plasma 6.1+ — InputCapture, RemoteDesktop/EIS — с 6.0;
- wlroots (Sway), Hyprland, COSMIC, niri — нет InputCapture (у Hyprland в работе).

## Решение

- Порталы через `ashpd 0.13` (MIT; модули `input_capture`, `remote_desktop`), протокол EI через `reis 0.7`
  (MIT, чистый Rust, без C-libei). `reis` в ранней стадии — изолируем за трейтами платформы; запасной путь —
  FFI к libei (лицензия libei — MIT, сверить при подключении).
- Восстановление разрешения через restore token портала, где композитор поддерживает; иначе диалог при каждом
  запуске сессии — честно показываем это в онбординге.
- **Запасной режим** при отсутствии порталов: курсор не переходит через край; переключение на другое устройство
  хоткеем, ввод в этом режиме захватывается только когда окно Bridge в фокусе — честное сообщение в UI
  «Ваш композитор (Sway) не поддерживает InputCapture: доступен режим переключения по хоткею».
  Дополнительно: если запущен XWayland и пользователь согласен — подсказка о сеансе X11.
- Инъекция на Wayland-приёмнике: RemoteDesktop + EIS; если нет — устройство в раскладке помечается
  «только источник».
- Drag&drop: сохранение в папку + уведомление (ADR-0008).

## Последствия

- Тестов в CI с настоящим композитором на этапе 1 нет (нужен GNOME/KDE в контейнере с порталами — ROADMAP),
  в MANUAL_TESTS — GNOME 46+ и Plasma 6.1+.
