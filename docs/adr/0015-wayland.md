# ADR-0015. Linux Wayland

Статус: Принято (веха 4c; на настоящем композиторе не проверено)

## Контекст

Wayland намеренно не даёт глобального перехвата и инъекции. Официальный путь — порталы xdg-desktop-portal:
InputCapture (захват после барьера на краю) и RemoteDesktop с `ConnectToEIS` (инъекция), данные идут через libei.

Поддержка на октябрь 2026:
- GNOME 46+ — InputCapture и RemoteDesktop (версия 2 портала с буфером — GNOME 50+);
- KDE Plasma 6.1+ — InputCapture, RemoteDesktop/EIS — с 6.0;
- wlroots (Sway), Hyprland, COSMIC, niri — нет InputCapture (у Hyprland в работе).

## Решение

- Порталы через `ashpd 0.13` (MIT; модули `input_capture`, `remote_desktop`), протокол EI через `reis 0.7`
  (MIT, чистый Rust, без C-libei). `reis` в ранней стадии — изолируем за трейтами платформы; запасной путь —
  FFI к libei (лицензия libei — MIT, сверить при подключении).
- Восстановление разрешения через restore token портала, где композитор поддерживает; иначе диалог при каждом
  запуске сессии — честно показываем это в онбординге.
- **Запасной режим** при отсутствии порталов: курсор не переходит через край; переключение на другое устройство
  хоткеем, ввод в этом режиме захватывается только когда окно Bridge в фокусе — честное сообщение в UI
  «Ваш композитор (Sway) не поддерживает InputCapture: доступен режим переключения по хоткею».
  Дополнительно: если запущен XWayland и пользователь согласен — подсказка о сеансе X11.
- Инъекция на Wayland-приёмнике: RemoteDesktop + EIS; если нет — устройство в раскладке помечается
  «только источник».
- Drag&drop: сохранение в папку + уведомление (ADR-0008).

## Реализация (веха 4c)

- `bridge_platform::native()` выбирает Wayland-бэкенд при `XDG_SESSION_TYPE=wayland` (или при `WAYLAND_DISPLAY`
  без `XDG_SESSION_TYPE`). `BRIDGE_INPUT_BACKEND=x11` принудительно включает X11 — для XWayland-отладки.
- Порталы асинхронные (zbus), поэтому бэкенд держит свой поток с однопоточным tokio-runtime. Синхронные трейты
  платформы общаются с ним через каналы. `native()` вызывается внутри runtime демона, так что вложенного
  `block_on` нет.
- При старте проверяется, есть ли порталы. Если нет ни одного, возвращается `Unsupported` с текстом для
  пользователя. Если есть один, устройство работает наполовину: «только источник» или «только приёмник»,
  с предупреждением в журнале.
- **Захват.** Сессия InputCapture (Keyboard | Pointer). Барьеры ставятся на все внешние края зон: край, к
  которому примыкает другая зона, пропускается. Барьеры правого и нижнего края стоят на пиксель за зоной, как
  требует портал. Активация на барьере превращается для `InputRouter` в толчок на 2 px за край в точке
  активации. Если роутер переход не принял (с той стороны никого нет), захват сразу отпускается с курсором
  на 2 px внутри. Пока захват активен, события EIS (receiver) — это поток «под захватом»: относительные
  движения с накоплением дробной части, кнопки evdev, discrete-скролл (1/120, знак по вертикали
  инвертируется), клавиши evdev. Возврат: роутер шлёт `Grab(false)` и следом `Warp`. Бэкенд ждёт `Warp`
  до 50 мс и вызывает `Release` с этой позицией курсора.
- **Инъекция.** RemoteDesktop (Keyboard | Pointer, `PersistMode::ExplicitlyRevoked`). Restore token лежит в
  `$XDG_STATE_HOME/bridge/remote-desktop.token`. Дальше `ConnectToEIS`, EI sender, `start_emulating` на
  каждом возобновлённом устройстве, кадр `frame` после каждой операции. Абсолютное движение идёт через
  `ei_pointer_absolute` в координатах регионов устройства. Регионы же служат экранами, если InputCapture нет.
- Синхронизация раскладки и Lock-клавиш на Wayland не поддерживается: ни один портал их не даёт
  (`TODO(M4c+)`). Режим «переключение по хоткею» без InputCapture требует окна в фокусе, поэтому он
  переносится в веху 9 (UI).
