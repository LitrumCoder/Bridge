# ADR-0011. Пользовательский демон и локальный IPC

Статус: Предложено

## Контекст

Сетевое ядро должно работать без открытого окна. Перехват/инъекция ввода, буфер и drag&drop доступны только
из пользовательского сеанса рабочего стола.

## Решение

- `bridged` — процесс в сессии пользователя, один на сессию (lock-файл / именованный мьютекс).
- Автозапуск: Windows — `HKCU\…\Run`; macOS — LaunchAgent в `~/Library/LaunchAgents`; Linux — systemd `--user` unit,
  XDG autostart как запасной вариант. Установка/удаление автозапуска — команды демона, UI их вызывает.
- IPC: локальный сокет / именованный канал (crate `interprocess`, `0BSD OR Apache-2.0`; если его tokio-API
  не подойдёт — тонкая собственная обёртка над `tokio::net::windows::named_pipe` и `UnixStream`).
  Доступ только владельцу (DACL / права каталога + проверка UID клиента).
- Кадры `u32 длина + postcard`; `Request{id, body}` → `Response{id, body}`; `Subscribe` → поток `Event`.
- Версия IPC отдельна от версии сетевого протокола.
- Конфигурация и данные: `directories` (MIT/Apache) — `config.toml`, `trust.toml`, ключи, журнал, staging.

## Альтернативы

- **Демон внутри Tauri-процесса.** Закрытие UI убивает сеть; CLI зависит от UI.
- **Системная служба.** Нет доступа к рабочему столу пользователя без отдельного агента; оставлена как
  опциональный компонент для UIPI (ROADMAP).
- **gRPC/HTTP на localhost.** Порт виден другим пользователям машины, лишний стек.

## Последствия

CLI и UI тестируются против демона с mock-платформой в интеграционных тестах.
