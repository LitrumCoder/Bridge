# ADR-0005. Захват и инъекция ввода

Статус: Предложено

## Контекст

На устройстве с физическими мышью и клавиатурой нужно (а) наблюдать курсор, чтобы заметить уход за край,
(б) после ухода подавлять локальную доставку событий и получать относительные смещения,
(в) на целевом устройстве инъектировать события. Залипших клавиш быть не должно ни при каких сбоях.

## Решение

### Представление на проводе
- Клавиши — **USB HID Usage Page 0x07** (физическая позиция). Таблицы «скан-код ОС ↔ HID» для каждой ОС —
  в `platform`, с тестом «обход туда-обратно» для каждой таблицы.
- Кнопки мыши — `Left/Right/Middle/Back/Forward`, колесо — в единицах 1/120 щелчка (hi-res) по двум осям.
- Движения — абсолютная позиция на экране получателя + `seq` (ADR-0006).

### По ОС

| ОС | Наблюдение и захват | Подавление | Инъекция | Разрешения |
|---|---|---|---|---|
| Windows | `WH_MOUSE_LL`, `WH_KEYBOARD_LL` в выделенном потоке с message loop | хук возвращает ненулевое значение; смещение = `pt` события − позиция парковки | `SendInput` | не нужны |
| macOS | сессионный `CGEventTap` (`kCGEventTapOptionDefault`) | возврат `NULL` из колбэка + `CGAssociateMouseAndMouseCursorPosition(false)`; смещения из `kCGMouseEventDeltaX/Y` | `CGEventPost` | Accessibility (активный tap и постинг) |
| X11 | XInput2 raw events + барьер XFixes на внешних краях для обнаружения ухода | активный `XGrabPointer`/`XGrabKeyboard` на служебное окно, курсор паркуется `XWarpPointer`, смещения из `XI_RawMotion` | XTest `FakeInput` | не нужны |
| Wayland | см. ADR-0015 | — | — | диалог портала |

Колбэк хука/tap'а вызывает `InputRouter` синхронно (ADR-0001), решение «пропустить или проглотить» принимается
сразу, исходящие события уходят в очередь сетевой задачи. Хук ничего не ждёт: на Windows хук, не уложившийся
в `LowLevelHooksTimeout` (не более 1000 мс начиная с Windows 10 1709), молча снимается системой. Поэтому есть
сторожевой механизм: поток хука раз в 500 мс шлёт себе тестовое сообщение и при пропаже хука ставит его заново
и сообщает в журнал.

### Инвариант отпускания
- Источник: `KeyTracker` хранит адрес доставки каждой нажатой клавиши/кнопки; отпускание идёт туда же.
  Нажатия, попавшие в локальную ОС до ухода курсора, не подавляются при отпускании.
- Приёмник: `InjectedSet` на каждый источник, полное отпускание при любом `PeerDown`, закрытии потока
  `InputEvents`, `ReleaseAll`, паузе, выходе, idle timeout.
- Модификаторы при входе: `Enter` несёт состояние CapsLock/NumLock; приёмник синхронизирует только «залипающие»
  состояния, удерживаемые модификаторы не переносятся.

### Хоткеи
Определяются в `core` как последовательности HID-кодов; аварийный возврат дублируется прямо в коде хука,
чтобы работать при зависшем ядре.

### macOS: как сделано (веха 4c)

- Привязки: `objc2-core-graphics`, `objc2-core-foundation`, `objc2-application-services` 0.3.2 (MIT/Zlib/Apache).
- Координаты раскладки на macOS — **точки** глобального пространства дисплеев, то есть те же единицы, что у
  событий. Это не backing-пиксели. Масштаб Retina идёт в `scale_permille` (`CGDisplayModeGetPixelWidth` /
  ширина в точках). Размер в мм берётся из `CGDisplayScreenSize`.
- Tap: `kCGSessionEventTap`, голова очереди, `Default`. Поток с `CFRunLoop`, источник в `kCFRunLoopCommonModes`.
  - Свою инъекцию отличаем по `kCGEventSourceUserData` = `"BRDG"`.
  - `FlagsChanged`: модификаторы приходят без признака «нажато/отпущено». Направление определяем по набору
    удерживаемых кодов. Caps Lock приходит как переключение, поэтому отдаём пару «нажатие + отпускание».
  - Колесо: строки ×120, у трекпада (`IsContinuous`) — точки ×12 (10 точек на щелчок). Горизонталь
    инвертируется: на macOS положительное значение — влево.
- Инъекция идёт в `kCGHIDEventTap`, чтобы система сама учитывала модификаторы.
  - При зажатой кнопке шлём `*MouseDragged`, иначе приложения не видят перетаскивание.
  - Счётчик кликов (`MouseEventClickState`) ведём сами: 500 мс и 4 точки. Без него не работает двойной клик.
  - Текст шлём блоками по 20 UTF-16 единиц через `CGEventKeyboardSetUnicodeString`.
- Онбординг: `AXIsProcessTrusted()`. Если доступа нет — `AXIsProcessTrustedWithOptions(prompt)` и
  `PermissionRequired` с путём в настройках.
- Не сделано (`TODO(M4c+)`, LIMITATIONS): синхронизация раскладки через Text Input Sources.

## Альтернативы

- **Raw Input на Windows** (рекомендуется MS для чтения). Не умеет подавлять события — для «grab» всё равно нужен хук.
- **Готовые crates (`rdev`, `enigo`, `inputbot`).** Не дают синхронного подавления с решением per-event на всех ОС,
  не покрывают XI2-барьеры и Wayland-порталы; `enigo` годится, но нам нужен единый слой с mock-реализацией.
- **Передача символов вместо кодов клавиш.** Ломает хоткеи, игры и сочетания; раскладки синхронизируются отдельно.

## Последствия и ограничения (→ LIMITATIONS.md)

- Windows: `SendInput` подчиняется UIPI — окна с повышенными правами, UAC-диалоги, экран блокировки
  недоступны. Вариант решения (как в Mouse Without Borders) — опциональная служба SYSTEM; вынесено в ROADMAP,
  т.к. это отдельная поверхность атаки.
- macOS: без Accessibility работать не можем — нужен онбординг с проверкой `AXIsProcessTrusted()` и кнопкой
  открытия настроек. Приложение не в песочнице (App Store невозможен). При Secure Event Input (поля паролей)
  tap не получает клавиши. Отзыв Accessibility при активном tap'е на свежих macOS может подвесить ввод —
  при получении `kCGEventTapDisabledByUserInput` tap снимается немедленно.
- X11: отдельные экземпляры X-серверов (несколько сессий) не поддерживаются; тачскрины обходят барьеры.
